# 揭棋（暗棋象棋）规则文档

> 本文档描述本项目的**当前生效规则**，是游戏逻辑与判定的权威说明。
> 如对走法、布局、终局判负等规则做任何改动，**必须同步更新本文档**，并保持文末「维护指引」中列出的源码位置一致。

---

## 一、游戏概述

揭棋是中国象棋的变体：除将/帅外，其余棋子初始**背面朝下（暗子）**且**随机分布于初始位置**。棋子在被首次移动时翻面揭示真实兵种。本项目的棋盘为标准的 **10 行 × 9 列**（行 0–9，列 0–8；行 0 为黑方底线，行 9 为红方底线），红方先行。

---

## 二、棋子与初始布局

| 兵种 | 数量（每方） | 初始状态 |
|------|--------------|----------|
| 将 / 帅 | 1 | 明子，固定于底线中路（黑 `row0,col4` / 红 `row9,col4`） |
| 车 | 2 | 暗子，随机分布 |
| 马 | 2 | 暗子，随机分布 |
| 炮 | 2 | 暗子，随机分布 |
| 象 / 相 | 2 | 暗子，随机分布 |
| 士 / 仕 | 2 | 暗子，随机分布 |
| 兵 / 卒 | 5 | 暗子，随机分布 |

- 每方共 **16 枚**，其中 **15 枚为暗子**（将/帅除外）。
- 暗子通过 Fisher–Yates 洗牌后随机放置到标准初始位置，因此布局每局不同。
- 暗子以「?」显示，移动时翻面显示真实兵种。

## 三、走子规则（各兵种）

> 说明：`暗子`在翻面前，**按其所在棋格的标准兵种走法移动**（即"该格本应是什么子，就怎么走"）；**首次移动翻面后**，按其**真实兵种**的走法移动。

### 将 / 帅
- 在己方九宫内，沿直线走 **一步**（上下左右）。
- 不可出宫。

### 士 / 仕
- **未翻面**：在己方九宫内斜走一步。
- **翻面后**：可斜走一步，**不受九宫与河界限制（可过河）**。

### 象 / 相
- 走 **田字**（斜向两格），有**塞象眼**限制（田字中心点有子则不能走）。
- **未翻面**：不可过河（仅限己方半场）。
- **翻面后**：**可以过河**。

### 马
- 走 **日字**，有**蹩马脚**限制（前进方向的相邻正交格有子则不能走该方向）。

### 车
- 沿直线（横/竖）滑动任意步，路径上不能越过其他棋子；落点可为空或敌方子。

### 炮
- **不吃子时**：同车，沿直线滑动任意步。
- **吃子时**：必须**翻山**（隔且仅隔一个棋子作炮架），吃掉炮架后第一个敌子。

### 兵 / 卒
- **未过河**：只能向前走一步。
- **过河后**：可向前或左右走一步（不可后退）。

### 飞将（将帅照面）
- 红黑将/帅**不可在同一列、且中间无子隔断**时形成照面。
- 若走子后导致两将照面，该着法**非法**（被 `isInCheck` 判定为被将，过滤掉）。

### 翻面（暗子揭示）
- 任何暗子的第一步移动都会将其翻为明子（`hidden = false`）。
- 翻面不改变其所在位置，仅改变后续走法与显示。

## 四、合法性判定

一步着法合法需同时满足：
1. 由**当前回合方**走出；
2. 落点在棋子的合法走法集合内；
3. 走完后**己方将/帅不被将军**（含飞将照面情形）。

非法着法在 UI 中不可选，引擎层 `getLegalMoves` 已自动过滤。

---

## 五、终局与判定（胜负 / 和棋）

终局判定在 `executeMove` 完成后进行，结果写入 `BoardState.status` 与 `endReason`。

| 终局情形 | 判定 | `endReason` |
|----------|------|-------------|
| **将死** | 轮到走棋的一方**被将军且无任何合法着法** → 对方胜 | `将死` |
| **困毙** | 轮到走棋的一方**无合法着法（未被将军）** → 对方胜（按中国象棋惯例，无棋可走即负） | `困毙` |
| **长将判负** | 三次重复局面时，判定其中一方在循环内**每步都在将军** → 该方负 | `长将判负` |
| **长捉判负** | 三次重复局面时，判定其中一方在循环内**每步都在捉同一枚子** → 该方负 | `长捉判负` |
| **重复局面和棋** | 三次重复局面，且无一方违规（或双方都违规）→ 和棋 | `三次重复局面，和棋` / `双方均不变着，和棋` |
| **连将兜底判负** | 同一方**连续 6 次将军**却仍未形成重复局面 → 该方负 | `长将判负` |
| **无吃子和棋** | 连续 **60 个半回合（=30 回合）** 内无任何吃子 → 和棋 | `长时间无吃子，和棋` |

**判定顺序（先命中先生效）：** 将死 / 困毙 → 重复局面裁决 → 连将兜底 → 无吃子和棋。
若一手棋直接将死对方，即使该方此前在长将/长捉，也判其胜。

### 5.1 重复局面裁决（长将 / 长捉的统一入口）

**核心思路**：长将与长捉的共同特征是「局面反复出现」，因此用重复局面作为**触发器**，触发后再判定「谁在生事」。

1. **局面指纹**：棋子分布 + 每枚子的**明暗状态** + 轮到谁走。暗子与明子视为不同局面。
2. **回溯窗口**：吃子与翻子都是**不可逆**操作，之前的局面永不再现，因此回溯到最近一次吃子/翻子即停止。揭棋中窗口通常很短。
3. **触发条件**：同一指纹出现 **3 次**（`REPETITION_LIMIT = 3`）。
4. **裁决**：取出循环内的全部着法，分别判定红黑双方（见 `judgeCycle`）：
   - 该方着法中**含闲（idle）** → 不变着，不算违规（一将一闲 / 一捉一闲 / 纯闲）；
   - 该方每步**都是将军** → 长将；
   - 该方**含捉且捉住同一枚子**（取所有「捉」着法的目标交集非空）→ 长捉
     （其中「一将一捉」也视为生事，按**长捉**判负）；
   - 该方**含捉但捉的不是同一枚子**（目标无交集）→ 保守判为不变着（宁可和棋，不误判）；
   - **仅一方违规** → 该方判负；**双方均违规或都不违规** → 和棋。

### 5.2 「捉」的判定标准

一步走完后，判定本方是否「捉」住对方某枚子（`computeChases`），需同时满足：

- 本方**能真实吃掉**该子（吃完后本方不被将军）；
- 目标**不是将/帅**（那属于「将」而非「捉」）；
- 目标**不是未过河的兵/卒**（棋规视为「闲」）；
- 攻击子**不是帅/将、也不是兵/卒**（棋规视为「闲」）；
- 目标**无根（无保护）**，或目标价值**高于**攻击子价值（否则属于「兑」，算闲）。

暗子真实身份未知，其期望价值取**同色未翻暗子的平均真实价值**（贝叶斯近似：不知道它是谁，但知道剩下的暗子里有哪些）。`HIDDEN_CHASE_VALUE = 300` 仅在所有暗子都已翻开时的退化默认值。

> **精度说明**：已覆盖「一将一捉」「双方均长将」「长捉须捉同一子」等核心细分裁决；未覆盖「捉后可反捉」「解将还将」「长拦 / 长跟」等更复杂组合。对未覆盖情形保守判为和棋，因此**不会出现无限循环**，最坏情况只是把本该判负的局面判成和棋。

### 可配置常量
| 常量 | 位置 | 默认值 | 含义 |
|------|------|--------|------|
| `REPETITION_LIMIT` | `src/engine/repetition.ts` | `3` | 同一局面出现几次触发裁决 |
| `PERPETUAL_CHECK_LIMIT` | `src/engine/moves.ts` | `6` | 连将兜底判负的次数上限 |
| `NO_CAPTURE_DRAW_PLIES` | `src/engine/moves.ts` | `60` | 无吃子判和的半回合数（=30 回合） |
| `HIDDEN_CHASE_VALUE` | `src/engine/moves.ts` | `300` | 捉子判定中暗子的估值 |

> **AI 说明**：搜索引擎（`src/ai/search.ts`）已**感知**重复局面与长将/长捉规则。搜索树在每条路径上维护局面指纹（`positionKey`）与每步性质（将/捉/闲），一旦同一局面在路径上出现 `REPETITION_LIMIT` 次即调用 `judgeCycle` 裁决：违规方被判负（大负分并剪枝），和棋则记 0。AI 因此既**不会主动长将/长捉自杀**，也能在对方违规时主动制造重复逼胜/逼和。
>
> **UI 提示**：`src/engine/repetition.ts` 导出只读函数 `getRepetitionHint(board)`，对同一局面出现 `REPETITION_WARN(=2)` 次时给出⚠️预警（含「红方/黑方涉嫌长将/长捉」或「双方不变着判和」的推断）；游戏面板（`src/components/GamePanel.tsx`）在开局进行中展示该预警横幅，并提供「棋规说明」弹窗讲解暗子、胜负、长将长捉裁决与和棋等核心规则。

## 六、记谱（棋谱记录）

采用中文象棋记谱法，记录于每步 `Move.notation`：
- **纵线标注**：红方用中文数字（一、二、三…九），黑方用阿拉伯数字（1、2…9）。
- **着法格式**：`兵种 + 起点纵线 + 走法(进/退/平) + 落点`。
  - 例：红 `炮二平五`、`马八进七`；黑 `车8平4`。
- **翻面**：若着法翻开暗子，会标注揭示出的真实兵种。
- **将军/将死**：`isCheck` 在 UI 走子记录中以「+」提示，将死以「将死!」标注。

导出功能见 `src/utils/exportGame.ts`（支持 TXT 中文棋谱与 JSON 结构化棋谱）。

## 七、显示与交互

- **对方上一步加强显示**：棋盘上最近一步（即对方的上一步）以**橙色高亮圈 + 移动箭头 + 单元格底色**强显示；其前一步（己方上一步）以**蓝色弱高亮**作对照。
- **走子记录**：列表最后一步以橙色左边框 + 底色 + 加粗突出。
- **重复局面 / 长将长捉预警**：当同一局面出现 2 次（`REPETITION_WARN`），面板顶部以橙黄横幅提示「×方涉嫌长将/长捉，再次重复将判负/和棋」，便于玩家及时收手或逼和。
- **被吃暗子保密（吃子方可知、被吃方不可知）**：被吃掉的暗子（尚未翻开即被吃）其身份，**吃子方（对方）立即知悉**并照常显示为真实兵种；**被吃方（原属方）在棋局进行中看不到**，显示为「?」（灰色虚线圈），**直到棋局结束才揭晓**。走子记录中的「吃?」同样按查看方视角在终局前对被吃方隐藏，对吃子方显示真实兵种。已翻明的子被吃则照常显示。单屏热座 PvP 下以默认方（`playerColor`）视角呈现，属已知局限。
- **棋规说明弹窗**：面板提供「棋规说明」按钮，弹出揭棋速览（暗子翻面、被吃暗子保密、胜负、长将/长捉裁决、和棋与连将兜底、AI 感知）。
- 实现位置：`src/components/Board.tsx`（棋盘高亮）、`src/components/GamePanel.tsx`（列表高亮、终局文案、⚠️预警横幅、被吃暗子「?」显示、棋规弹窗），规则推断见 `src/engine/repetition.ts`（`getRepetitionHint`）；保密判定见 `src/engine/board.ts`（`isCapturedRevealed`）。
