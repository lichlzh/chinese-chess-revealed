# 揭棋引擎自我对弈（AI vs AI）模拟说明

本文档说明为评估「红方 / 黑方胜率」所做的引擎自我对弈实验的具体方法与口径，便于复现与核对。

## 1. 目的

用**同一套 AI** 分别执红、执黑进行大量对局，统计双方胜负与和棋比例，借此观察引擎是否存在先手/后手或红黑两色的胜率偏差。本质是**镜像对弈（mirror match）**：同一引擎与自己下，衡量的是引擎层面的平衡性，而非人机对战水平。

## 2. 环境与依赖

- 项目为 TypeScript + Vite + Vitest（`npx vitest run` 可执行单个测试文件）。
- 对局逻辑直接复用项目内的真实引擎代码，**不另写一套规则**：
  - `src/engine/board.ts`：`initBoard()` 生成含暗子的初始局面。
  - `src/engine/moves.ts`：`executeMove(state, from, to)` 执行一步并推进局面、判定终局。
  - `src/ai/search.ts`：`findBestMove(state, config, tt)` 迭代加深搜索，返回最佳着法。
  - `src/ai/tt.ts`：`TranspositionTable` 置换表。
- 临时对弈脚本以 Vitest 测试文件形式存在（不在主流程中），结果通过 `console.log` 输出到日志。

## 3. 模拟方式

### 3.1 单局流程

对每一局：

1. `initBoard()` 生成初始局面（红黑各 16 子，其中 15 枚为暗子）。
2. 设置先手方 `state.currentTurn`（红先手或黑先手，见第 4 节）。
3. 新建一个置换表 `tt`（**每局一个**，局内红黑双方共享、互相升温）。
4. 进入循环，直到 `status !== Playing` 或达到着法上限 `CAP = 300`：
   - `const { move } = findBestMove(state, CONFIG, tt);` —— 当前行棋方用 AI 选着。
   - `const res = executeMove(state, move.from, move.to);` —— 用真实规则执行该步。
   - `state = res.newState; plies++;`
5. 依据 `state.status`（`RedWin` / `BlackWin` / `Draw`）累计胜负，并记录 `endReason`（终局原因）。

### 3.2 终局判定（来自 `executeMove`，即真实棋规）

- **将死 / 困毙**：`isCheckmate` 为真 → 对方胜（`endReason` 为 `'将死'` 或 `'困毙'`）。
- **三次重复局面**：`countRepetition >= REPETITION_LIMIT` → 调用 `adjudicateRepetition` 裁决长将/长捉/不变作和（`endReason` 如 `'三次重复局面，和棋'`、`'长将判负'`、`'长捉判负'`）。
- **长将判负**：`checkPerpetualCheck` 检测到一方长将 → 该方判负。
- **长时间无吃子和棋**：`movesWithoutCapture >= NO_CAPTURE_DRAW_PLIES` → 和棋（`'长时间无吃子，和棋'`）。
- **兜底截断**：若 300 着内仍未终局，视为「未完成」计入和棋侧（`endReason` 记为 `'截断'`）。

> 早期曾用 `CAP = 64`，导致约一半对局被截断、和棋虚高；最终统一采用 `CAP = 300`，使绝大多数对局能自然终局（将死为主）。

### 3.3 暗子视角的公平性

AI 在评估与走法生成时统一调用 `getEffectiveType(piece, pos)`：

- 暗子（`hidden === true`）按**位置身份**走子/评估，即 AI 并不读取其隐藏的真实 `type`，因此**不会「偷看」暗子**；
- 翻开后（`hidden === false`）才以真实 `type` 走子，双方都能看见。

故对局在暗子信息上是对等的，模拟的是「双方都按规则只知明子、暗子按位置身份处理」的公平博弈。

## 4. AI 与关键参数

- 搜索：`findBestMove` 采用**迭代加深 + 置换表 + 负极大（negamax）+ 静态搜索（quiescence）**，从第 1 层加深到 `maxDepth`，并以 `timeLimit`（毫秒）作为每步预算；时间检查约每 64–128 个节点做一次（`Date.now() - searchStartTime > timeLimit`），因此部分着法会略超预算。
- 红黑双方使用**完全相同**的参数与同一函数，保证镜像公平。
- 可调参数（通过环境变量）：
  - `SP_DEPTH`：最大搜索深度（默认 `6`）。
  - `SP_TIME`：每步时间预算毫秒（默认 `20`）。
  - `SP_FIRST`：先手方，`red`（默认）或 `black`。

### 复现命令

红先手（标准开局）：

```bash
npx vitest run src/engine/selfplay.test.ts
# 等价于：SP_FIRST=red SP_DEPTH=6 SP_TIME=20 npx vitest run src/engine/selfplay.test.ts
```

黑先手（用于区分「先手劣势」与「红方引擎偏向」）：

```bash
SP_FIRST=black SP_DEPTH=6 SP_TIME=20 npx vitest run src/engine/selfplay.test.ts
```

> 对局脚本以 Vitest 运行，故每局进度与最终统计通过 `console.log` 输出；脚本内部曾有一处 `expect(plyCap).toBe(300)` 的宽松断言与统计无关，不影响打印出的胜率数据有效性。

## 5. 两次实验与结果

实验均在本地（macOS）以单进程后台运行，每局约 1.7–21 秒（见第 6 节异常）。

### 5.1 红先手（标准开局）100 局

| 结果 | 局数 | 占比 |
|---|---:|---:|
| 红方胜 | 30 | 30.0% |
| 黑方胜 | 60 | 60.0% |
| 和棋   | 10 | 10.0% |

- 平均 82.0 着/局；终局原因：将死 84、长将判负 6、三次重复和棋 8、长时间无吃子和棋 2。
- **后手（黑）以 2:1 占优。**

### 5.2 黑先手 100 局（对照实验）

| 结果 | 局数 | 占比 |
|---|---:|---:|
| 红方胜 | 41 | 41.0% |
| 黑方胜 | 46 | 46.0% |
| 和棋   | 13 | 13.0% |

- 平均 79.6 着/局；终局原因：将死 83、三次重复和棋 10、长时间无吃子和棋 3、长捉判负 1、长将判负 3。

### 5.3 解读

若引擎完全对称，「先手胜率」是一个与颜色无关的固定值 X（后手胜率 = 1−X）。红先手样本给出先手（红）30%，黑先手样本给出先手（黑）46%——两批都是围绕同一真值 X 的噪声抽样（X≈38%，两批分别偏离约 −8pp / +8pp，均在 ~1.3 个标准误内）。因此**没有证据支持引擎存在颜色偏向**；数据一致地指向一个普遍成立的「后手优势」（后手方胜率约 60%+），即先手（红）30% / 后手（黑）60% 与先手（黑）46% / 后手（红）41% 实为同一现象的两面。

## 6. 根因结论（经定位）

1. **「12× 耗时异常」是测量假象，不是引擎 bug。** 早期探针因解构错误（`const { move } = findBestMove(...)`，而该函数返回的是 `{ from, to }`）误以为每局只走 1 步；修正为 `const { from, to }` 后，在真实对局条件（每局共享置换表、timeLimit=20、cap=300）下实测：红先手平均 20.9ms/步、黑先手 20.4ms/步，**无任何一步超过 100ms**。原黑先手批次后台运行时遭遇 CPU 争用/节流，墙钟时间虚高约 12 倍，并非搜索变慢。
2. **「红 30% / 黑 60%」是真实现象，源于后手优势 + 弱 AI 采样噪声，不是引擎颜色 bug。** 已通过多重手段确认引擎颜色对称：
   - 镜像探针：同一局面与其颜色镜像下，`findBestMove` 耗时（21.4ms vs 21.2ms）与根分支因子（32.4 vs 32.4）完全一致；
   - 静态审查：走法生成、评估（`pstAt` 对红方做 `9−row` 翻转、红正黑负）、搜索（负极大 + 符号翻转）、终局判定（`executeMove` 按 `currentTurn`/`verdict.loser` 翻转）均为形式对称；
   - `computeHash` 正确编码颜色（`pieceKeys[type][color][r][c]` + `sideKey`），置换表不会跨颜色混淆。
   揭棋中先手必须率先翻开暗子、暴露信息给对方，后手方据以回应具备信息优势，故**（对称引擎下的）后手占优**是合理结论；而 timeLimit=20ms 实际只搜到约 depth 2（实测单步仅约 100 节点），AI 极弱、对局结果噪声大，放大了样本波动。
3. **确定性对称验证的备注**：用 `timeLimit=20` 的弱搜索做「同开局互换颜色」全局面对照时，匹配率仅约 47%，初看像不对称；但这正是**时限非确定性噪声**所致（depth-2 弱 AI 在 20ms 截断下走子不稳定，同一类局面不同运行会翻盘）。改用确定性搜索（关时限、固定深度）可彻底排除，但因当时测试环境卡死未能跑完；如需 100% 确认，建议以 `SP_TIME=0 SP_DEPTH=3` 重跑该对照。

## 7. 局限与注意事项

1. **单样本噪声**：每局初始局面由 `Math.random` 随机生成（无固定随机种子），100 局为一单次抽样；约 90 局分胜负时，比例标准误约 ±6 个百分点，两批先手胜率（30% vs 46%）的差异主要属噪声。
2. **算力有限**：`depth=6`、`20ms/步` 实际只搜到约 depth 2，属于极弱配置；更强搜索可能改变平衡，更接近人类水平的「先手略优」结论。
3. **非人类棋风**：镜像对弈衡量引擎平衡性，不代表真实人机或人人对战的胜率分布；暗子按位置身份处理亦与「人类凭经验猜暗子」不同。

## 8. 附：对局脚本核心代码（重建）

```ts
import { initBoard } from './board';
import { executeMove } from './moves';
import { GameStatus, Color } from './types';
import { findBestMove } from '../ai/search';
import { TranspositionTable } from '../ai/tt';
import { describe, it, expect } from 'vitest';

const GAMES = 100;
const CONFIG = {
  maxDepth: parseInt(process.env.SP_DEPTH ?? '6', 10),
  timeLimit: parseInt(process.env.SP_TIME ?? '20', 10),
};
const FIRST = process.env.SP_FIRST === 'black' ? Color.Black : Color.Red;

describe('AI 自我对弈', () => {
  it('对弈并统计胜率', () => {
    let redWins = 0, blackWins = 0, draws = 0;
    let plyCap = 0, totalPlies = 0;
    const endReasons: Record<string, number> = {};

    for (let g = 0; g < GAMES; g++) {
      let state = initBoard();
      state.currentTurn = FIRST;            // 指定先手方
      const tt = new TranspositionTable();  // 每局一个，局内双方共享
      let plies = 0;
      const CAP = 300;                      // 着法上限，防止个别对局不收敛
      while (state.status === GameStatus.Playing && plies < CAP) {
        const { from, to } = findBestMove(state, CONFIG, tt);
        if (!from || !to) break;
        const res = executeMove(state, from, to);
        if (!res) break;
        state = res.newState;
        plies++;
      }
      plyCap = Math.max(plyCap, plies);
      totalPlies += plies;
      if (state.status === GameStatus.RedWin) redWins++;
      else if (state.status === GameStatus.BlackWin) blackWins++;
      else draws++;
      const reason = (state as any).endReason ?? '截断';
      endReasons[reason] = (endReasons[reason] ?? 0) + 1;
      if ((g + 1) % 10 === 0) console.log(`  ... ${g + 1}/${GAMES} games done`);
    }

    console.log(`\n===== AI 自我对弈 ${GAMES} 局 (先手=${FIRST}, depth=${CONFIG.maxDepth}, 每步预算 ${CONFIG.timeLimit}ms) =====`);
    console.log(`红方胜: ${redWins} (${((redWins / GAMES) * 100).toFixed(1)}%)`);
    console.log(`黑方胜: ${blackWins} (${((blackWins / GAMES) * 100).toFixed(1)}%)`);
    console.log(`和棋:   ${draws} (${((draws / GAMES) * 100).toFixed(1)}%)`);
    console.log(`平均着法数/局: ${(totalPlies / GAMES).toFixed(1)}`);
    console.log(`终局原因分布: ${JSON.stringify(endReasons)}`);
  });
});
```
